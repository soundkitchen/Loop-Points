# Lyria 出力 MP3 の調査と無劣化トリム方式

Google Gemini Lyria が書き出す MP3 を解析し、再エンコードなしでサンプル精度のトリムができるかを検証した記録。
調査日: 2026-11-09。対象: `samples/` の 4 ファイル(2026-11-07〜08 生成)。

## 1. ファイル構造(4 本とも共通)

| 項目 | 内容 |
|---|---|
| ストリーム | MPEG-1 Layer III、CBR 192kbps、44.1kHz、joint stereo、CRC なし |
| フレーム長 | 626 バイト(padding ビットありで 627 バイト) |
| Xing / Info / VBRI / LAME ヘッダ | なし(エンコーダ遅延・パディング情報なし) |
| 先頭タグ | ID3v2.3 が 1 つ。中身は `GEOB` フレーム(MIME `application/c2pa`)1 つのみ、約 6KB |
| 末尾 | ID3v1 なし、最終フレーム以降のデータなし |
| ビットリザーバ | ほぼ全フレームで使用(`main_data_begin > 0` が 96〜99%) |

### C2PA マニフェスト

`GEOB` には Google が署名した C2PA マニフェストストアが入っている。主な中身:

- `c2pa.created`: "Created by Google Generative AI."
- `c2pa.edited`: "Applied imperceptible SynthID watermark."
- `c2pa.hash.data`: ファイル本体のバイト列に対するハッシュ(hard binding)

トリムするとハッシュが一致しなくなり、検証に失敗する。K!LN は署名し直せない。

## 2. 検証結果

ffmpeg でデコードした PCM を、元ファイルのデコード結果と比べた。

1. **フレーム境界でそのまま切る**: 切った位置から 2 フレームが壊れる(RMS 誤差が信号と同程度)。原因はビットリザーバ(前のフレームのデータを参照する)と MDCT のオーバーラップ。
2. **切る位置より 2 フレーム手前から含める**: 目的のフレーム以降が元ファイルとビット一致する(2 ファイル × 2 か所で確認)。
3. **2 に加えて先頭に Info + LAME ヘッダのフレームを付け、encoder delay / padding で余分な部分を指定する**: 任意のサンプル位置で切った結果が、元ファイルのデコード結果の該当区間と **f32 でビット一致**し、長さも一致した(端数 0 / 300 / 1151 サンプルで確認)。s16 出力では ±1 の差が十数サンプル出るが、これは ffmpeg の量子化によるもの。

### ffmpeg の挙動で分かったこと

- 先頭でスキップされるサンプル数 = LAME タグの `delay` + 529(デコーダ遅延)
- 末尾の削除には Xing の `frames` フィールドと LAME タグの `padding` を使う
- LAME タグのエンコーダ名が `LAME` / `Lavf` / `Lavc` のどれかで始まらないと、delay / padding を無視する
- 入力をパイプで渡すとファイルサイズが分からず、末尾の padding が効かない(ファイルなら効く)

## 3. トリム方式(検証済みの手順)

切り出す区間を元ファイルのデコーダ出力上のサンプル位置 `[s0, e0)` で指定し、`spf = 1152` とする。

1. 開始フレーム `K = floor(s0 / spf)`、端数 `a = s0 - K * spf` を求める
2. フレーム `K - 2` から `e0` を含むフレームまでをそのまま連結する(先頭付近で `K < 2` の場合は、ある分だけ含める)
3. 先頭に Info フレームを付ける
   - フレームヘッダは元ストリームと同じ設定(padding ビットなし)
   - Xing 部: `Info` タグ、フラグは frames / bytes / TOC / quality の 4 つすべて(LAME タグが標準位置の +120 に来るようにするため)
   - LAME 部: `delay = (含めた余分なフレーム数) * spf + a - 529`、`padding = (連結したフレーム数) * spf - delay - (e0 - s0)`
   - LAME タグの CRC-16 を計算して書く(フレーム先頭から 190 バイト分)
4. ID3v2(C2PA)は付けない

`delay` と `padding` はどちらも 12bit(0〜4095)の範囲に収まる。

注意: `K < 2` で余分なフレームを 2 つ含められない場合、`delay` が負になりうる(`s0 < 529` のとき)。LAME タグ付きの出力では先頭 529 サンプル(デコーダ遅延ぶん)を再現できないため、`s0` は 529 以上に切り上げる。この区間は元ファイルでも実質無音。
