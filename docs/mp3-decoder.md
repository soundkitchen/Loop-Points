# MP3 デコーダ

MPEG-1 Layer III のデコーダ(`src/mp3/` の `bits` / `huffman` / `layer3` / `synth` / `decoder`)の設計と検証の記録。MP3 → WAV の書き出しに使う。扱う範囲は無劣化トリム(`docs/lyria-mp3.md` §5.1)と同じく MPEG-1 Layer III だけ。

## 1. 数表の出所

規格(ISO/IEC 11172-3)が定める数表のうち、計算で導けないものは [minimp3](https://github.com/lieff/minimp3)(CC0 1.0、パブリックドメイン相当)から取った。K!LN のライセンスを MIT に近いものにするため、LGPL の ffmpeg の表は使わない。

| 表 | 取り方 | 確かめたこと |
|---|---|---|
| ハフマン符号表(big_values 用の 15 表 + linbits、count1 の表 A / B) | minimp3 の `tabs` / `tab32` / `tab33` / `tabindex` / `g_linbits` を、先読みで引ける木の形のまま使う(形式は `src/mp3/huffman.zig` の冒頭) | どの表も符号が完全(Kraft の和が 1)で、(x, y) がすべて 1 回ずつ現れる。表 1 の全符号と、表 13 / 15 / 16 / 24 の (0,0) の符号が規格書と一致する(テスト) |
| 合成窓 D[i](Table B.3) | minimp3 の `g_win`(D[i] × 65536 の整数を並べ替えたもの)と `mp3d_synth_pair` の定数から D[0..256] を組み立て、D[512 - i] は対称性(i が 64 の倍数でなければ符号を反転)で作る | 組み立てた 257 個が、ffmpeg の `ff_mpa_enwindow` として知られる値と全項目一致し、規格書の代表値(D[1] = -0.000015259、D[256] = 1.144989014 など)とも一致する |

表はスクリプトで minimp3 のソースから抜き出して Zig のソースに書き出した(手で写していない)。

計算で作る表: スケールファクタ帯の境界(規格の値を書き、minimp3 の表と照合した)、pretab、scalefac_compress の (slen1, slen2)、エイリアス削減の係数(c_i から計算)、インテンシティステレオの比(tan から計算)、IMDCT の係数と窓、合成フィルタの行列。

## 2. 処理の流れ

1 フレーム(2 グラニュール)ごとに、次の順で処理する。IMDCT と合成フィルタは規格の式どおりに倍精度で計算し、出力だけ f32 にする。

1. サイド情報(`layer3.readSideInfo`)
2. ビットリザーバと、このフレームのメインデータを続けて読む(`decoder.Decoder`)
3. グラニュール・チャンネルごとに、スケールファクタ(scfsi による使い回しを含む)、ハフマン復号、逆量子化
4. ジョイントステレオの処理(MS、インテンシティ)
5. 短いブロックの並べ替え、エイリアス削減
6. IMDCT(窓、前のグラニュールとの重ね合わせ、周波数反転)
7. 32 帯の合成フィルタバンク

`kiln.mp3.decode` は入力全体を先頭から復号し、トリムと同じタイムライン(`docs/lyria-mp3.md` §5.1)で区間を切り出して渡す。Xing / Info のフレームは復号しない(ffmpeg と同じ)。

## 3. ffmpeg に合わせた細かい扱い

規格が決めていないところや、壊れた入力の扱いは、ffmpeg の mpegaudio デコーダ(mp3float)に合わせた。

- **ビットリザーバが足りないとき**: main_data_begin が残っているリザーバより大きければ、データが足りないグラニュールを無音にする(IMDCT の重ね合わせは続ける)。トリム結果の先頭のフレームなどで起きる
- **リザーバの持ち越し**: フレームを読み終えた位置(バイト単位に切り上げ)より後を、最大 512 バイトまで次のフレームに持ち越す。読みすぎたときはフレームの末尾 512 バイト
- **count1 の領域**: グラニュールの終わりを越えて読んだ最後の 4 値の組は捨てる
- **MS ステレオだけのとき**: 1/√2 を global_gain に含める(2 を引く)。インテンシティステレオと併用するときは、帯ごとに 1/√2 を掛ける
- **インテンシティステレオ**: 右チャンネルが 0 の高い帯から順に、位置 7(不正)でない帯に使う。最後の帯(長いブロックの 21、短いブロックの 12)は、その 1 つ前の帯の位置を使う
- **mixed block**: ブロックの種類によらず(開始・終了のブロックでも)、低い 2 サブバンドは通常の窓で IMDCT する
- **emphasis**: 予約値(2)を含めて見ない。この変更はトリムのフレームの判定にも効く

## 4. 検証

kiln で f32 の WAV に書き出した PCM を、`ffmpeg -c:a mp3float` の出力と比べた。

| 入力 | 長さ | ffmpeg との差の最大 |
|---|---|---|
| `testdata/` の 4 本、Lyria の実ファイル 4 本、lame で作った追加の 6 本(32〜320kbps、VBR、CRC 付き、48kHz) | すべて一致 | 2.7e-6(音量の大きい実際の曲。testdata は 1.4e-6 以下) |
| ISO の適合性試験のストリーム(ffmpeg の FATE の `mp3-conformance`): compl、he_32khz、he_44khz、he_48khz、hecommon、si、si_block、si_huff、sin1k0db | 下の既知の差を除いて一致 | 4.3e-6(si_huff。振幅が 7.85 ある信号で、相対誤差は 7.6e-7)。sin1k0db(0dB のサイン波)は 3.5e-6、ほかは 4e-7 以下 |

差は float の丸めによるもの(ffmpeg は逆量子化の一部を固定小数点で計算する)。

既知の差:

- **途中で切れた最後のフレーム**: kiln は数えない(トリムと同じ)。ffmpeg は足りない分を補ってデコードするので、1 フレーム長くなる(compl、sin1k0db)
- **チャンネル数が途中で変わるストリーム**: kiln は変わったところで終わりとみなす(he_mode はモノラルからデュアルチャンネルに変わる)
- **free format**: 扱わない(he_free)
- **サイド情報が壊れたフレーム**: kiln は無音にして続ける。ffmpeg はそのフレームを出力しない

確かめていない経路: インテンシティステレオ(適合性試験のストリームは si 系がモノラルで、hecommon / sin1k0db はインテンシティステレオを使っていない)。

速さ: 2 分 43 秒のステレオ(Lyria の実ファイル)の復号に、ReleaseFast で 0.8 秒、Debug で 7 秒(Apple Silicon の Mac)。
