# m4a(MP4 コンテナの AAC / ALAC)

m4a の読み込み(`src/m4a.zig`、`src/m4a/` の `box` / `asc`)と、AAC の無劣化の切り出し(`src/m4a/trim.zig`。§5)の設計と検証の記録。決定事項は [`draft.md`](draft.md) §2.8(解析)、§2.12(切り出し)。

## 1. 扱う範囲と出所

- コンテナは ISO/IEC 14496-12(ISO Base Media File Format)と 14496-14(MP4)、AAC の設定は 14496-3 §1.6.2.1(AudioSpecificConfig)、記述子は 14496-1(ES_Descriptor など)。Apple の `iTunSMPB` と QuickTime のサンプルエントリの版 1 も読む。外部のコードや表は取り込んでいない
- 先頭が `ftyp` ボックスでなければ `NotM4a`。`moov` がない・ボックスの長さが壊れている・サンプルの表(`stts` と `stsz`)が食い違う・長さの合計(`stts`、編集リスト)が 64 ビットを超える・サンプルレートが 0 などは `InvalidM4a`
- 最初の音声トラック(`hdlr` が `soun`)を見る。`hdlr` を読めないトラック(ボックスの長さが壊れているなど)は飛ばす。中身は AAC(`mp4a` で、記述子のオブジェクトタイプが MPEG-4 Audio か MPEG-2 AAC)と ALAC(`alac`)だけ。MP3 などの別のコーデック、音声トラックがないもの、断片化した MP4(`mvex` や `moof` がある)、QuickTime のサンプルエントリの版 2 は `UnsupportedFormat`
- 解析(`probe`)では音声データ(`mdat`)は読まない。最後のボックス(多くは `mdat`)が途切れていても、`moov` を読めていれば構わない。切り出し(`trim`)は `mdat` から AAC のフレームをコピーするので、サンプルのデータが入力の外を指す(途中で切れた)ものは `trimmable` が false で、`trim` は `UnsupportedFormat`(§5.2)

## 2. サンプルレートとチャンネル数

**AAC**: `esds` の DecoderSpecificInfo(AudioSpecificConfig。QuickTime では `wave` の中にあることもある)を読む。

- オブジェクトタイプ、サンプルレート、channelConfiguration(1〜6、7 → 8、11 → 7、12 / 14 → 8、13 → 24。0 はプログラム設定からチャンネル数を数える)
- SBR / PS の印は 2 通りある。先頭のオブジェクトタイプが 5(SBR)/ 29(PS)で、出力のレートと中心の方式が続くもの(明示的・階層的)と、中心の設定の後ろに同期ワード 0x2B7 と SBR の有無・出力のレート、0x548 と PS の有無が続くもの(後方互換)。ffmpeg は AAC-LC にも「SBR なし」を書き、afconvert は HE-AAC に後方互換の印を書く
- 印がないとき(暗黙の印。SBR は音声データの中にしかない): 中心のレートが 24kHz を超えるなら SBR はない(HE-AAC の中心は 24kHz まで)。メディアのタイムスケールかサンプルエントリのレートが中心の 2 倍なら SBR がある。どちらでもなければ分からない(`sbr` は null)
- PS は SBR の上でモノラルを 2 チャンネルに広げるもの。SBR がないか、中心がモノラルでなければ PS はない。分からなければ `ps` は null
- 結果のサンプルレートとチャンネル数はデコード結果のもの(SBR があれば出力のレート、PS があれば 2 チャンネル)
- AudioSpecificConfig のバイト列もそのまま返す(WebCodecs の `AudioDecoder` の `description` に使える)

**ALAC**: サンプルエントリの中の `alac` ボックス(ALACSpecificConfig)のビット深度・チャンネル数・サンプルレート。

## 3. 長さ

メディアの長さ(タイムスケールの単位)は `stts` の合計。そこから先頭の遅延と末尾の詰め物を除いた長さを、次の順で求める。

1. **編集リスト(`edts` / `elst`)**: 各編集の長さ(ムービーのタイムスケールの単位)をメディアのタイムスケールに直して足す。空の編集(media_time が -1。無音を挟む)も長さに含める。長さ 0 の編集はメディアの最後まで。先頭の遅延は、最初の空でない編集の開始位置(ffmpeg は AAC で 1024)
2. **`iTunSMPB`**(編集リストがないとき。`moov` か `trak` の `udta` / `meta` / `ilst` / `----`): 2 つ目の値が遅延、4 つ目が長さ(16 進)。長さが 0 か、遅延と長さの和がメディアの長さを超えるときは使わない(あふれないように、遅延と「メディアの長さ − 遅延」とで比べる)。afconvert は AAC で遅延 2112 と長さを書く。値はメディアのタイムスケールの単位(afconvert の HE-AAC は中心の 22.05kHz の単位)
3. どちらもなければ、メディアの長さをそのまま使う(遅延は 0)

最後に、タイムスケールの単位からデコード結果のサンプルレートの単位に直す(HE-AAC で、タイムスケールが中心のレートのときは 2 倍になる)。`meta` は ISO ではフルボックス、QuickTime ではただのボックスなので、中身が `hdlr` で始まるかで見分ける。

## 4. 検証

- テスト用のファイル(`testdata/` の ffmpeg の AAC-LC、afconvert の AAC-LC・HE-AAC・HE-AAC v2・ALAC)で、プロファイル・SBR / PS・サンプルレート・チャンネル数・長さ・遅延が ffprobe と元の長さに一致する(HE-AAC の遅延は、iTunSMPB の 2112 を 44.1kHz に直した 4224)
- 61 秒の曲を ffmpeg の AAC、afconvert の AAC-LC・HE-AAC・ALAC に変換したもので、長さが元の WAV と同じ 2,699,136 サンプルになる
- テスト用のファイルを壊したり途中で切ったりした入力で、Debug ビルドが止まらない

## 5. AAC の切り出し(2026-11-11)

`kiln.m4a.trim` / `trimAlloc`(JS は `m4a.trim`)。再生位置(デコード結果のレートのサンプル数)で区間を受け取り、AAC を再エンコードせずに、メディアのタイムスケールの単位で切り出す。AAC-LC はタイムスケールがサンプルレートと同じなのでサンプル単位、中心のレートのタイムスケールの HE-AAC(afconvert など)は 2 サンプル単位になる(先頭は切り捨て、終わりは切り上げ、実際の区間を返す)。

### 5.1 先に確かめたこと

Python の試作(フレームをコピーし、編集リストを書いたもの)で、44.1kHz ステレオの 10 秒の曲を ffmpeg の AAC-LC、afconvert の AAC-LC・HE-AAC・HE-AAC v2・ALAC にしたものを確かめた。

- Chromium 157 の `decodeAudioData` と ffmpeg 9.0 は、編集リスト(media_time と segment_duration)による前後の切り詰めを守る。iTunSMPB だけを書いたものも守る。編集リストと iTunSMPB の両方を書いても(同じ値なら)区間どおり。ffmpeg は編集リストがあっても iTunSMPB を読み、値をメディアのタイムスケールの単位として扱う(iTunSMPB だけ単位を変えると長さが崩れる)
- macOS の Apple のデコーダ(AudioToolbox。`afinfo` と `afconvert` で確かめた)は、編集リストを読まずに iTunSMPB だけを読む(編集リストだけのものは、遅延を既定の 2112 として扱う)。HE-AAC では、iTunSMPB の値を中心のレート(22.05kHz)の単位として読む。そのため、HE-AAC のタイムスケールを出力のレート(44.1kHz)に変えてその単位で iTunSMPB を書くと、Apple では長さと位置が崩れる。タイムスケールを元のまま(中心のレート)にすれば、Chromium、ffmpeg、Apple のどれでも区間どおりになる
- AAC は、区間の先頭を含むフレームの 1 つ前から復号すれば元と同じ値になる(afconvert の AAC-LC で差 0)。ffmpeg の AAC は PNS(ノイズを乱数で作る)を使うので、どこから復号しても差が出る(最大 0.007 ほど。PNS を切ってエンコードすると差 0)。HE-AAC は、前に残すフレームが 1 つだと SBR の差が 0.009 ほど残り、2 つにすると 0.001 ほどになる。それより増やしても、ほとんどの区間で変わらない
- 区間の終わりのフレームで出力が終わると、区間の先頭がそのフレームの後ろのほうにあるとき(44.1kHz で、最後のフレームの中に区間が 500 サンプル足らずしかないときなど)、Chromium はデコードに失敗し(`EncodingError`)、ffmpeg は何も出さない。後ろに 1 フレーム足すと直る。入力の末尾で足せるフレームがなければ、最後のフレームを繰り返して足しても直る
- HE-AAC v2 は、PS(パラメトリックステレオ)の情報がときどきしか送られないので、途中から復号すると左右が元と違う(差 0.2 ほど)。前に 30 フレーム残しても直らない
- Chromium は ALAC をデコードできない(元のファイルも `EncodingError`)

### 5.2 方式

- **選ぶフレーム**: 区間の先頭を含むフレームの 2 つ前(HE-AAC の SBR のため。AAC-LC は 1 つで足りる)から、区間の終わりより前に始まる最後のフレームの 1 つ後までをそのままコピーする。入力の末尾で後ろのフレームが足りなければ、最後のフレームを繰り返す(再生はされない)
- **タイムスケール**: 元のまま。区間はタイムスケールの単位に直す(先頭は切り捨て、終わりは切り上げ)。HE-AAC で出力のレートに変えないのは、Apple と ffmpeg が iTunSMPB を違う単位で読むため(§5.1)
- **位置**: 再生位置 t(タイムスケールの単位)は、メディアの先頭(デコード結果の先頭)から数えて t + 先頭の遅延(§3)の位置にある。編集リストの media_time は、最初にコピーしたフレームの先頭から区間の先頭まで、segment_duration は区間の長さ(ムービーのタイムスケールもメディアと同じにする)
- **ボックス**: ftyp(元のまま)、moov、mdat の順に作り直す。moov は mvhd、trak(tkhd、edts / elst、mdia(mdhd(言語は元のまま)、hdlr(元のまま)、minf(smhd と dinf は元のまま、stbl(stsd は元のまま、stts、stsc と stco は 1 チャンク、stsz))))、udta。長さや位置が 32 ビットに収まらなければ版 1 のボックス(と mdat の 64 ビットの長さ)にする。mdat の中身の位置は moov の後ろなので、stco の 32 ビットで足りる。sgpd / sbgp(ffmpeg が書く roll の情報)などは書かない
- **iTunSMPB**: moov の udta / meta / ilst に、遅延(media_time)、末尾の詰め物、長さ(segment_duration)を、タイムスケールの単位で書く(Apple の作るファイルと同じ単位)。元の udta のほかのタグ(曲名など)は残し、元の iTunSMPB は消す。udta がなければ meta(ハンドラ mdir)と ilst を作る。トラックの udta は書かない
- **扱わない入力**(`probe` の `trimmable` が false、`trim` は `UnsupportedFormat`): ALAC、HE-AAC v2(§5.1)、SBR / PS の有無が分からないもの(出力のレートが決まらない)、タイムスケールがデコード結果のレートの整数分の 1 でないもの、空の編集や複数の編集のある編集リスト、遅延と長さがメディアに収まらない編集リスト、サンプルの説明が複数あるもの、stz2、サンプルの表が食い違うもの、データが入力の外を指すもの(途中で切れたファイル)

### 5.3 検証

- 10 秒の曲を afconvert の AAC-LC・HE-AAC、ffmpeg の AAC-LC(44.1kHz ステレオ、PNS あり / なし。48kHz モノラル)にし、区間の途中、先頭と末尾の近く、全体、1 サンプル、奇数の位置、末尾の 1〜5000 サンプルなど 102 通りを kiln で切り出した
  - Chromium と ffmpeg で、長さはすべて実際の区間どおり。元のファイルをデコードしたものの区間の部分との差は、afconvert の AAC-LC と PNS なしの ffmpeg で 0、PNS ありの ffmpeg で最大 0.0066、HE-AAC で最大 0.001(§5.1)
  - Apple のデコーダ(`afconvert` で WAV にする。48kHz モノラルは除く)でも長さはすべて区間どおりで、元のファイルを Apple でデコードしたものとの差は、HE-AAC で末尾を含む区間の最後の数サンプルが 0.014 ほどのほかは 0.001 以下
  - kiln の `probe` で、長さが区間どおりで、`trimmable` が true
- テスト: testdata の AAC-LC 2 本と HE-AAC で、いくつかの区間の実際の区間(HE-AAC は 2 サンプル単位)と長さ、フレームが元のバイト列のままでタイムスケールも元のままであること(入力の末尾では最後のフレームを繰り返すこと)、出力の位置 0 が元の区間の先頭を指すこと(最初にコピーしたフレームの開始位置と遅延から)、iTunSMPB が編集リストと同じ値であることを確かめる。ほかに、udta のタグを残して iTunSMPB だけを書き直すこと、サンプルの表の読み方、範囲外と扱えない入力(ALAC、HE-AAC v2、途中で切れたもの、編集リストの値がメディアに収まらないもの)
- **未確認**: Safari と Firefox、Apple のデコーダを使うほかのプレイヤー
