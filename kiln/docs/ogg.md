# Ogg(Vorbis / Opus)

Ogg の読み込み(`src/ogg.zig`、`src/ogg/` の `page` / `vorbis` / `opus`)と、Opus の無劣化の切り出し(`src/ogg/trim.zig`。§6)の設計と検証の記録。Vorbis の切り出しは後の PR で足す。決定事項は [`draft.md`](draft.md) §2.8。

## 1. 扱う範囲と出所

- コンテナは RFC 3533(Ogg)、Opus のヘッダとグラニュール位置は RFC 7845(Ogg Opus)、Opus パケットの長さは RFC 6716 §3.1、Vorbis のヘッダは Vorbis I specification から書いた(外部のコードや表は取り込んでいない)
- ページの CRC-32 は Zig の標準ライブラリの `std.hash.crc.Generic`(多項式 0x04C11DB7、初期値 0、反転なし、最後の XOR なし)
- 扱うのは、論理ビットストリームが 1 本だけで、中身が Vorbis か Opus のファイル。Ogg FLAC は形式の判定で FLAC になり(`kiln.flac` が `UnsupportedFormat` を返す)、Speex・Theora などは `UnsupportedFormat`
- 複数のストリームを多重化したもの(先頭に BOS のページが複数)と、連結したもの(EOS の後に新しい BOS)は `UnsupportedFormat`
- 先頭は `OggS` で始まっていなければならない(`NotOgg`)。音声データは読まない(デコーダはない)

## 2. ページとパケット

- ページは `OggS`、版(0)、フラグ(続き / BOS / EOS)、グラニュール位置、serial、ページ番号、CRC、セグメントの長さの表と本文。CRC が合わない・版が 0 でないページと、ページの間のゴミは、次の `OggS` まで飛ばして数える(`invalid_pages`)。入力の終わりで途切れたページも 1 つと数える
- パケットはセグメントの長さが 255 未満のところで終わり、ページをまたいで続くことがある。ヘッダのパケット(Vorbis の設定ヘッダは数 KB になる)は、ページをたどりながら 1 バイトずつ読む(`page.PacketReader`)。メモリは確保しない
- ページ番号が飛んでいたら(ページが欠けている)、続いていたパケットは捨てる。読めずに飛ばしたページがなければ、その欠けも 1 つと数える。ヘッダのパケットをページをたどって読むときも、ページ番号が続いていなければそこでパケットの終わりとみなす
- 最初のページは BOS で、その最初のパケットが識別ヘッダ。`OpusHead` なら Opus、`\x01vorbis` なら Vorbis

## 3. ヘッダ

**Opus**: `OpusHead`(版の上位 4 ビットが 0 のものだけ。チャンネル数、pre-skip、エンコード前のサンプルレート、チャンネルの割り当て方)と、2 つ目のパケットの `OpusTags`。デコード結果は常に 48kHz で、グラニュール位置もこの単位。エンコード前のレート(`input_sample_rate`)は参考の値で、デコードには使わない(opusenc は元の WAV のレートを書く。0 は不明)。

**Vorbis**: 識別ヘッダ(版 0、チャンネル数、サンプルレート、2 つのブロックの長さ 64〜8192)、コメントヘッダ、設定ヘッダの 3 つ。設定ヘッダは末尾のモードの表(各モードが長いブロックか)を知るためだけに読む。モードの表は最後にあるので、コードブック・時間領域の変換・フロア(0 と 1)・レジデュー・マッピングを、構造をたどって読み飛ばす(値の表は読み捨てる。パケットが足りなければ `InvalidOgg`)。ビットは LSB から順に読む。

## 4. 長さ

グラニュール位置は、そのページで終わる最後のパケットまでを復号したときのサンプル位置(-1 はこのページで終わるパケットがないこと)。長さは最後のグラニュール位置から、先頭の位置を引いて求める。

- 先頭の位置 = 最初に音声パケットが終わるページのグラニュール位置 − そこまでの音声パケットの長さの合計
  - Opus のパケットの長さは、先頭のバイト(TOC)の構成番号とフレーム数から(符号 3 は 2 バイト目)。120ms を超える壊れたパケットと空のパケットは 0
  - Vorbis のパケットの長さは、前のパケットのブロックの長さ / 4 + 今のパケットのブロックの長さ / 4(最初のパケットは 0)。ブロックの長さは、パケットの先頭のモード番号とモードの表から
- 先頭の位置が正なら、途中から切り出したストリーム(その分だけ短い)。負なら、最初のページが最後のページでもあれば末尾の切り詰め、そうでなければ先頭の切り詰め(Vorbis I の仕様)で、どちらも再生は位置 0 から始まる
- `samples` = 最後のグラニュール位置 − max(先頭の位置, 0) − pre-skip(Opus だけ)。負になれば 0
- 音声パケットがないファイルは長さ 0。ヘッダが揃う前に終わっていれば `InvalidOgg`

最初の音声ページが壊れて読めないときは、次のページから先頭の位置を求める(その分は長さに入らない)。最後のページが壊れていれば、その前のページの位置までが長さになる。

## 5. 検証

- テスト用のファイル(`testdata/` の opusenc・ffmpeg の Opus、oggenc の Vorbis。0.5 秒)で、長さ・pre-skip・元のレートが opusinfo / ogginfo と一致する
- 61 秒の曲を opusenc・ffmpeg(libopus)・oggenc で変換したもので、長さが opusinfo / ogginfo と一致する(Opus は 48kHz で 2,937,836 サンプル、Vorbis は元の WAV と同じ 2,699,136 サンプル)
- テストで最初のページのグラニュール位置を書き換え、途中から切り出したストリーム(長さが減る)、先頭の切り詰め、1 ページだけのときの末尾の切り詰めを確かめる。最後のページを壊したとき、途中で切れたとき、2 つのファイルを連結したときも確かめる
- テスト用のファイルを壊したり途中で切ったりした入力(各 200 通り。一時的に 3,000 通りでも確かめた)で、Debug ビルドが止まらない

## 6. Opus の切り出し(2026-11-11)

`kiln.ogg.trim` / `trimAlloc`(`src/ogg/trim.zig`)。JS は `ogg.trim`。再エンコードせず、区間をサンプル単位で切り出す。

### 6.1 方式

Opus は、前後の余分をサンプル単位で捨てさせる仕組みを仕様に持つ(RFC 7845)。それを使い、音声パケットはそのままコピーする。

- **位置の数え方**: 再生位置 t(pre-skip を除いた、48kHz のサンプル数)は、デコード結果の先頭から数えて t + pre-skip + max(0, −先頭の位置)。先頭の位置は §4 と同じ求め方
- **使うパケット**: 開始位置が「区間の先頭 − 80ms(3840 サンプル)」以下の最後のパケットから、開始位置が区間の終わりより前の最後のパケットまで。80ms は RFC 7845 §4.6 が勧める、デコーダの状態がそろうまでの長さ。ファイルの先頭に近ければ、取れる分だけ残す
- **先頭の余分**: ID ヘッダの pre-skip を「区間の先頭 − 最初に使うパケットの開始位置」に書き換える(16 ビットに収まらなければ `InvalidOgg`。80ms と最大 120ms のパケットなので、ふつうは収まる)
- **末尾の余分**: 最後のページのグラニュール位置を「pre-skip + 区間の長さ」にする。デコーダは、そこから後ろを捨てる(RFC 7845 §4.5 の末尾の切り詰め)
- **ページ**: 作り直す。ID ヘッダだけの最初のページ(BOS)、コメントヘッダ(元のまま。1 ページに入らなければ次のページへ続ける)、音声のページの順。音声は 1 ページに 1 秒分(255 セグメントまで)ずつ入れ、各ページのグラニュール位置は、そのページで終わる最後のパケットまでの長さ。最後のページは EOS。serial は元のまま、ページ番号は 0 から、CRC は付け直す
- **扱わない入力**: Vorbis(後の PR)、読めないページや欠けたページがあるもの(`InvalidOgg`。欠けた分の位置が分からないため)、壊れたパケット(120ms を超える)

### 6.2 検証

- 61 秒の曲の 10 秒を、opusenc(44.1kHz の WAV から)と ffmpeg(libopus、48kHz)で Opus にし、区間の途中(100000〜300000)、先頭の近く(1000〜50000。80ms 取れない)、末尾(400000〜480000)、1 サンプル(123457〜123458)を切り出した
  - opusinfo の長さ、kiln の `probe`、ffmpeg と Chrome の `decodeAudioData`(48kHz)の長さが、どれも区間どおり
  - ffmpeg と Chrome で、元のファイルを同じデコーダでデコードしたものと位置がずれない(±300 サンプルで探して、ずれ 0)。80ms 前から復号するので、区間の先頭からの差は信号の 1e-4 ほど(先頭の近くは 0)
- テスト: testdata の 2 本で、いくつかの区間の長さが区間どおりになること、パケットが元のバイト列のままであること、区間の前に 80ms 残すこと、途中から切り出したストリーム(最初のグラニュール位置が先にある)、範囲外と扱えない入力、1 ページに入らないパケットのページの作り方を確かめる
- **未確認**: Unreal Engine など、ゲームエンジンのデコーダが pre-skip と末尾の切り詰めを守るか(Loop Points の #16)
