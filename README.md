# Loop Points

音源のループポイント(ループする区間の開始と終了)を波形を見ながら決め、JSON に書き出す web ツールです。音源の前後を切り落として書き出すこともできます。

音源はブラウザ内で処理し、アップロードしません。

公開版: https://loop-points.soundkitchen.workers.dev/

## 動かす

Node.js `^24.22.1` または `>=26.12.1` が必要です(それぞれのセキュリティ更新を適用したバージョン以降)。

```sh
npm install
npm run dev     # 開発サーバー。表示された URL を開く
npm run build   # 型チェックのあと、dist/ に静的ファイルを出力する
```

## 使い方

1. 音源を「音源を開く」で選ぶか、ページにドロップします(mp3 / wav / ogg / opus / m4a / aac / flac / webm)。複数の音源を読み込むと、セレクトで切り替えられます
2. 続きから作業するときは、JSON を「JSON を読み込む」で選ぶか、ページにドロップします
3. 前後の不要な部分を切り落とすときは、[クロップモード](#クロップ)で切り出します
4. 波形を見ながら、ループの開始と終了を決めます
5. JSON に保存します

### ループポイントの指定

| 方法 | 内容 |
|---|---|
| 波形上でドラッグ | 「開始」「終了」の線を動かします。「ドラッグでゼロクロスに吸着」がオンなら、近く(10px 以内)のゼロクロスに寄せます |
| 数値の入力 | 秒またはサンプルで入力します。吸着せずにその位置へ置きます |
| 微調整のボタン | ±1 サンプル、±1ms、±10ms ずらします。「◀ 0」「0 ▶」で前後のゼロクロス(1 秒以内)へ移ります |
| 拡大 | その点を中心に 20ms の幅を表示します |

ゼロクロスは、全チャンネルを平均したモノラルの波形が 0 を横切る位置です。ちょうど 0 のサンプルも含むので、無音の区間では全サンプルがゼロクロスになり、吸着はその場に留まり、「◀ 0」「0 ▶」は 1 サンプルずつしか進みません。ステレオでは、左右が同じ位置で 0 を横切るとは限りません。

### つなぎ目の確認

| ボタン | 内容 |
|---|---|
| ▶ 頭から | 曲頭から再生します。イントロを 1 回流したあと、ループ区間を繰り返します |
| ▶ つなぎ目の手前から | ループの終わりの数秒前(既定は 3 秒)から再生し、開始点へ戻る所をすぐ聴けます |
| ▶ カーソルから | 波形をクリックして置いたカーソルから再生します。カーソルがループの終わり以降にあるときは、開始点から再生します。<kbd>Space</kbd> でも再生と停止ができます |

再生中にループ区間を動かすと、止めずに反映します。ただし、再生位置が新しい区間の外に出たときは、新しい開始点から鳴らし直します。

### 表示の操作

- 縦のホイール(トラックパッドのピンチ)で拡大縮小、横のスクロールで左右に移動します
- 波形の何もない所をドラッグするとスクロール、クリックするとカーソルを置きます
- 下の全体表示をクリックやドラッグすると、その場所へ移動します
- 画面の配色は、右上のボタンでシステム、ライト、ダークから選べます。選択はブラウザに保存し、開いている別のタブにも反映します

## クロップ

波形の上の「クロップ」に切り替えると、音源の前後を切り落として書き出せます。動かす線が「前端」「後端」に変わり、切り落とす部分は暗く表示します。線のドラッグ、数値の入力、微調整のボタンは、ループポイントと同じです。範囲は音源ごとに保ち、モードを切り替えても消えません。

形式はセレクトで選びます。初期値は元の形式で、書き出せない形式(m4a、flac など)の音源は WAV です。

| 書き出す形式 | 書き出し方 |
|---|---|
| WAV | 元が WAV(PCM または float)なら、バイト列をそのまま切り出します。音質、ビット深度、サンプルレートは変わりません。音声以外のチャンクは引き継ぎません。元が別の形式なら、16-bit で書きます |
| mp3 | 192kbps の固定ビットレートで再エンコードします。2ch までです。サンプルレートは 32 / 44.1 / 48kHz のどれかです |
| Ogg Vorbis | 品質 6(mp3 と同じくらいのサイズ)で再エンコードします。2ch までです。`.ogg` の中身が Opus の音源も Vorbis になります |

再エンコードするときは、分かる範囲で元のサンプルレートを保ちます。m4a、aac、WebM は元のレートが分からないので、`AudioContext` のレートになります。

ファイル名は `bgm-cropped.mp3` のように、`-cropped` と選んだ形式の拡張子を付けます。保存先を選べるのは Chromium 系のブラウザで、それ以外はダウンロードします。

- 保存先を選ぶときは、選んだ形式の拡張子のまま保存してください。拡張子を変えると、書き出さずに止めます(中身と拡張子が食い違うと、開き直したときやゲームエンジンで形式を読み違えるため)
- ダウンロードでは、同じ名前のファイルがあると、ブラウザが `bgm-cropped (1).mp3` のように名前を変えることがあります。ページは実際の名前を知ることができず、JSON には `bgm-cropped.mp3` で項目を作ります。その音源を開いている間は注意を表示するので、名前が変わっていたら直してください

書き出すと、次のようになります。

- 書き出した音源を開き、ループモードに戻ります。元の音源はセレクトに残ります
- ループを決めていた音源なら、前を切った分を引いた秒数で、書き出した音源の項目を作ります。元の音源の項目も残します。JSON の保存は別の操作で、それまでは未書き出しと表示します
- ループを決めていない音源なら、項目は作りません。全体がループ区間のままです

ループを決めた音源で、クロップの範囲がループ区間にかかっている間は、警告を出して書き出しを止めます。線を区間の外へ動かすか、ループモードで区間を動かしてください。

再生は前端から後端まで 1 回で止まり、ループしません。線を動かすと止まります。

## JSON の保存

| 操作 | Chrome、Edge などの Chromium 系 | Firefox、Safari など |
|---|---|---|
| JSON を書き出す | 保存先を選んで保存します | `loops.json` をダウンロードします |
| 上書き保存 | 読み込んだ、または保存した JSON に上書きします | 使えません |
| JSON をコピー | クリップボードにコピーします | 同じ |

- 保存はファイル全体の置き換えです。ほかの音源の項目を残すには、先にその JSON を読み込みます
- 読み込んだあとにファイルが外から変更されていたら、上書きする前に確認します
- ダウンロードは成否を判定できないので、押した時点で書き出し済みとして扱います。コピーは書き出し済みとして扱いません
- 再読み込みすると、読み込んだ音源と未保存の変更は消えます。未書き出しの変更があるときは、閉じる前にブラウザの確認が出ます

## JSON の形式

ファイル名ごとに、`loopStart` と `loopEnd` を秒で持ちます。`duration` はデコード後の長さ(秒)です。

```json
{
  "bgm.mp3": {
    "loopStart": 10.5,
    "loopEnd": 50.25,
    "duration": 60
  }
}
```

- 秒で持つのは、`AudioContext` のサンプルレートが変わってもずれないようにするためです。小数 6 桁に丸めるので、サンプル境界からごくわずかにずれることがあります
- `duration` がない JSON も読めます。音源を開いた時点で補います
- `duration` と音源の長さが 1ms を超えて違うと、警告を出します。区間を動かすと、今の音源の長さで記録し直します
- 区間を動かしていない音源は、JSON に書きません。読み込んだ JSON にある項目と、音源の項目の中の知らないフィールドは残します
- 音源の項目でないキー(`$schema` など)や、値が正しくない項目が 1 つでもあると、ファイル全体を読み込みません
- ファイル名の順に並べて書くので、差分が読みやすくなります

`AudioBufferSourceNode` には、次のようにそのまま渡せます。

```js
const src = ctx.createBufferSource();
src.buffer = buffer;
src.loop = true;
src.loopStart = loops[name].loopStart;
src.loopEnd = loops[name].loopEnd;
src.connect(ctx.destination);
src.start(0, 0);   // 頭から鳴らすと、イントロを 1 回流してからループ区間を繰り返す
```

## 注意点

- **mp3 の先頭と末尾の無音**: mp3 にはエンコーダが入れる数十ミリ秒の無音があります。長さの情報(LAME ヘッダ)があるファイルは、Chrome、Firefox、Safari がこの無音を取り除くので、位置も長さも元の音源と揃います。情報がないファイルは無音が残り、Chrome、Firefox と Safari で 529 サンプル(44.1kHz で約 12ms)ずれます。このツールの mp3 には情報を書きます。ffmpeg で mp3 にするときは既定のままにし、`-write_xing 0` を付けないでください
- **Ogg Vorbis の位置**: Safari は Vorbis の音源を 128 サンプル(44.1kHz で約 2.9ms)前にずれた位置でデコードし、長さも短くなることがあります。Chrome と Firefox ではずれません。Safari で切り出すと、元の音源のずれにも重なります。10ms 程度以下に切り出した Vorbis は、ブラウザによって開けないことがあります
- **再エンコードの音質**: mp3 や Ogg で書き出すと音質が少し落ちます。元が非可逆圧縮の音源だと、圧縮を重ねることになります。波形も少し変わるので、ループの位置はゼロクロスからずれることがあります。書き出したあとに合わせ直してください
- **WebM**: `AudioContext` と違うサンプルレートの WebM は、デコード後の位置がブラウザによって数十サンプルずれることがあります(48kHz の Opus を 44.1kHz でデコードしたとき)
- **サンプルレート**: `decodeAudioData` はデコードしたあと、`AudioContext` のサンプルレートに変換します。ゼロクロスは変換後の波形で探すので、別のサンプルレートで鳴らすと、ゼロクロスからわずかにずれることがあります

## デプロイ

Cloudflare Workers の静的アセットとして `dist/` を配信します。サーバー側の処理はありません。設定は `wrangler.jsonc` にあります。

公開版は、`main` に push するたびに [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) が自動でデプロイします。ビルドの Node は `.node-version` で指定します。失敗しても公開版は前のバージョンのままで、失敗は Cloudflare のダッシュボードのビルド履歴で確認します。手元で確認したり、手動でデプロイしたりするときは、次のコマンドを使います。

```sh
npx wrangler login   # 初回のみ
npm run build
npx wrangler dev     # dist/ を Workers のランタイムで手元に配信する
npm run deploy       # ビルドして、Cloudflare にデプロイする
```

- `wrangler dev` と `wrangler deploy` はビルドしません。`npx wrangler deploy` を直接実行すると、古い `dist/` を公開するおそれがあるので、`npm run deploy` を使ってください
- 手動でデプロイするときは、レビュー前の内容を公開しないように、`main` で実行してください
- Workers Builds の設定はリポジトリに含まれません。fork で自動デプロイを使うときは、`wrangler.jsonc` の `name` と `account_id` を接続先の Worker に合わせ、Cloudflare のダッシュボードでリポジトリを接続して、ビルドコマンドに `npm run build` を指定してください
- `wrangler.jsonc` の `account_id` は、デプロイ先の Cloudflare アカウントです。fork して自分のアカウントにデプロイするときは、書き換えてください
- デプロイすると、`<name>.<サブドメイン>.workers.dev` を誰でも開けます(`name` は `wrangler.jsonc` の Worker 名)。音源はサーバーに送りません
- `public/_headers` の CSP で、外部への通信と他サイトへの埋め込みをブラウザに止めさせます。`'wasm-unsafe-eval'` は mp3 と Ogg のエンコーダ(wasm)のために許可しています。ページの遷移など、CSP で止められない経路もあります。CSP が付くのは Cloudflare と `wrangler dev` の配信だけで、`npm run dev` には付きません
