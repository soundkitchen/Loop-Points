# Loop Points

音源のループポイント(ループする区間の開始と終了)を波形を見ながら決め、JSON に書き出す web ツールです。音源の前後を切り落として書き出すこともできます。

音源はブラウザ内で処理し、アップロードしません。

Chrome、Edge などの Chromium 系のブラウザで使えます。JSON を保存先に直接書き込むために [File System Access API](https://developer.mozilla.org/docs/Web/API/File_System_API) を使うので、この API のないブラウザ(Firefox、Safari、iPhone と iPad のすべてのブラウザなど)では、案内を表示して止まります。この API は HTTPS か `localhost` でしか使えないので、開発サーバーを別のマシンから `http://192.168.x.x` のように開くと、Chrome でも案内が出ます。

公開版: https://loop-points.soundkitchen.workers.dev/

## 動かす

Node.js `^24.22.1` または `>=26.12.1` が必要です(それぞれのセキュリティ更新を適用したバージョン以降)。

音源の解析とクロップの書き出しに使う kiln([`kiln/`](kiln/))の wasm のビルドに、Zig 0.17.1 を使います。`npm run dev` と `npm run build` は、先に kiln の wasm をビルドします。PATH に Zig 0.17.1 がなければ、公式のアーカイブを Zig のコミュニティのミラー(最後は ziglang.org)から `.zig/` に取ってきて、sha256 を確かめてから使います(初回は数十 MB のダウンロードと、wasm のビルドに時間がかかります)。手で入れた Zig を使うときは、リポジトリ直下の `.envrc`(direnv)で PATH に通せます。

```sh
npm install
npm run dev     # 開発サーバー。表示された URL を開く
npm run build   # 型チェックのあと、dist/ に静的ファイルを出力する
npm run kiln:test   # kiln のテスト(Zig のテスト、kiln.ts の実行時のテスト、型の検査)
```

- 開発サーバーが wasm をビルドするのは起動するときだけです。動かしたまま `kiln/` の Zig のソースを直したときは、`npm run kiln:build` でビルドし直してから、ブラウザを再読み込みしてください
- `npm run build` の最後に、`dist/` に `.wasm` のファイルが出ていないことを確かめます。kiln.wasm は、最初の音源を開くときに読むチャンクに埋め込むもので、別のファイルとして出ると、CSP(`connect-src 'none'`)で読み込めず、元のサンプルレートを調べられなくなり(出力の機器のレートに変換して開きます)、クロップの書き出しもできなくなるためです

## 使い方

1. 音源を「音源を開く」で選ぶか、ページにドロップします(mp3 / wav / ogg / opus / m4a / aac / flac)。音源を開くまでは、読み込みの案内だけを表示します。複数の音源を読み込むと、セレクトで切り替えられます
2. 続きから作業するときは、JSON を「JSON を読み込む」で選ぶか、ページにドロップします。音源より先に読み込むと、案内に JSON の名前と項目の数を表示し、音源を開いたときに反映します
3. 前後の不要な部分を切り落とすときは、[クロップモード](#クロップ)で切り出します
4. 波形を見ながら、ループの開始と終了を決めます
5. JSON に保存します

### ループポイントの指定

| 方法 | 内容 |
|---|---|
| 波形上でドラッグ | 「開始」「終了」の線を動かします。「ドラッグでゼロクロスに吸着」がオンなら、近く(10px 以内)のゼロクロスに寄せます |
| 数値の入力 | 秒またはサンプルで入力します。吸着せずにその位置へ置きます |
| 微調整のボタン | ±1 サンプル、±1ms、±10ms ずらします。「◀ 0」「0 ▶」で前後のゼロクロス(1 秒以内)へ移ります |
| 拡大 | その点を中心に 20ms の幅を表示します |

ゼロクロスは、全チャンネルを平均したモノラルの波形が 0 を横切る位置です。ちょうど 0 のサンプルも含むので、無音の区間では全サンプルがゼロクロスになり、吸着はその場に留まり、「◀ 0」「0 ▶」は 1 サンプルずつしか進みません。ステレオでは、左右が同じ位置で 0 を横切るとは限りません。

波形、ゼロクロス、「サンプル」の値は、音源の元のサンプルレートのものです(「[注意点](#注意点)」の「サンプルレート」を参照)。

### つなぎ目の確認

| ボタン | 内容 |
|---|---|
| ▶ 頭から | 曲頭から再生します。イントロを 1 回流したあと、ループ区間を繰り返します |
| ▶ つなぎ目の手前から | ループの終わりの数秒前(既定は 3 秒)から再生し、開始点へ戻る所をすぐ聴けます |
| ▶ カーソルから | 波形をクリックして置いたカーソルから再生します。カーソルがループの終わり以降にあるときは、開始点から再生します。<kbd>Space</kbd> でも再生と停止ができます |

再生中にループ区間を動かすと、止めずに反映します。ただし、再生位置が新しい区間の外に出たときは、新しい開始点から鳴らし直します。

### 表示の操作

- 縦のホイール(トラックパッドのピンチ)で拡大縮小、横のスクロールで左右に移動します
- 波形の何もない所をドラッグするとスクロール、クリックするとカーソルを置きます
- 下の全体表示をクリックやドラッグすると、その場所へ移動します
- 画面の配色は、右上のボタンでシステム、ライト、ダークから選べます。選択はブラウザに保存し、開いている別のタブにも反映します

## クロップ

波形の上の「クロップ」に切り替えると、音源の前後を切り落として書き出せます。動かす線が「前端」「後端」に変わり、切り落とす部分は暗く表示します。タブの横に、クロップ後の長さ、書き出す形式、「切り出して保存」のボタンが出ます。線のドラッグ、数値の入力、微調整のボタンは、ループポイントと同じです。範囲は音源ごとに保ち、モードを切り替えても消えません。

書き出しには、このリポジトリの [kiln](kiln/)(Zig 製、wasm)を使います。クロップモードに切り替えると kiln で音源を調べ、調べ終わると書き出せるようになります。形式は、拡張子ではなく中身(ファイルのヘッダー)で判定します。ただし mp3 は、中身に印がないので、拡張子が .mp3 のものだけを mp3 として扱います。形式は音源によって次のようになります。

| 音源 | 書き出す形式 | 書き出し方 |
|---|---|---|
| mp3 | mp3(初期値)、WAV、FLAC | mp3 は再エンコードせずに、サンプル単位で切り出します。音質は変わらず、長さの情報(LAME タグなど)を書くので、デコードした長さは切り出した区間と同じになります。WAV にするときは、デコードして 16-bit で書きます。kiln で読めない mp3(MPEG-2 など)は、ブラウザでデコードして WAV か FLAC だけに書き出します |
| FLAC | FLAC(初期値)か WAV | FLAC は FLAC のまま切り出します。区間の先頭と末尾にかかるフレームだけを作り直す可逆の処理で、音は変わりません。タグと画像は残します。WAV にするときは、kiln でデコードして、元のビット深度(24-bit なら 24-bit)のまま書きます。kiln で読めない FLAC は、ブラウザでデコードして WAV か FLAC だけに 16-bit で書き出します |
| WAV | WAV(初期値)か FLAC | 元の形式(ビット深度、サンプルレート)のまま切り出します。音声以外のチャンクは引き継ぎません |
| Opus(.opus / .ogg) | Opus(初期値)、WAV、FLAC | Opus は再エンコードせずに、サンプル単位で切り出します。区間の前の 80ms と一緒に音声のパケットをそのままコピーし、前後の余分はファイルの中の指定(pre-skip と末尾の位置)で捨てさせます。拡張子は元の音源に合わせます。WAV にするときは、ブラウザでデコードして 16-bit で書きます。壊れたページがあるものや、ブラウザでデコードした長さとファイルの長さが合わないものは、WAV か FLAC だけに書き出します |
| Ogg Vorbis(.ogg) | Ogg(初期値)、WAV、FLAC | Ogg Vorbis は再エンコードせずに切り出します。音声のパケットをそのままコピーし、末尾の余分はファイルの中の指定(末尾の位置)で捨てさせるので、末尾はサンプル単位で区間どおりです。先頭はパケットの区切りでしか切れないので、前端より少し前(44.1kHz の一般的なファイルで最大 1024 サンプル、約 23ms)の区切りから切り出し、その位置を知らせます。WAV にするときは、ブラウザでデコードして 16-bit で書きます。壊れたページがあるもの、先頭の余分を捨てる指定(最初のページの位置)が入ったもの(ブラウザがこの指定を守らず、位置が合わないため)、ブラウザでデコードした長さとファイルの長さが合わないものは、WAV か FLAC だけに書き出します |
| m4a の AAC(.m4a) | m4a(初期値)、WAV、FLAC | AAC は再エンコードせずに、サンプル単位で切り出します(HE-AAC は 2 サンプル単位で、前端は最大 1 サンプル前、後端は最大 1 サンプル後ろに寄ります)。区間の前の 2 フレームと後ろの 1 フレームと一緒に音声のフレームをそのままコピーし、前後の余分はファイルの中の指定(編集リストと iTunSMPB の両方)で捨てさせます。タグは残します。WAV にするときは、ブラウザでデコードして 16-bit で書きます。HE-AAC v2(途中から切り出すと左右のバランスが元と変わるため)や、ブラウザでデコードした長さとファイルの長さが合わないものは、WAV か FLAC だけに書き出します。ALAC はブラウザで開けません |
| aac(ADTS)など | WAV(初期値)か FLAC | ブラウザでデコードして、16-bit で書きます |

- FLAC の音源以外も、FLAC で書き出せます。WAV にするときと同じようにデコードして(mp3 と WAV は kiln で、ほかはブラウザで)、kiln で FLAC にエンコードします。16-bit で書きますが、整数の WAV は元のビット深度のまま(音は変わりません)、浮動小数点の WAV は 24-bit で書きます。FLAC は劣化せずに WAV より小さくでき、Unity(Unity 6 から)と Unreal Engine が読み込めます
- サンプルレートは元の音源のものを保ちます(元の形式のまま切り出す mp3、FLAC、Ogg、m4a はもちろん、WAV や FLAC にするときも)。ただし、元のレートが分からない音源(「[注意点](#注意点)」の「サンプルレート」を参照)は、出力の機器のレートになります
- 長さの情報のない mp3 は、先頭のデコーダの遅延(529 サンプル、44.1kHz で約 12ms)より前から無劣化で切り出せません。前端をそれより前に置くと、その位置から切り出して知らせます。ループを決めた音源で、そのずれでループの開始が削れるときは、警告を出して mp3 では書き出せないようにします(WAV なら書き出せます)
- Ogg Vorbis の先頭は、前端より前のパケットの区切りに寄せるので、前端より少し前の音が入ります。ループの開始は削れません。ループを決めた音源では、実際に切り始めた位置からの秒数で項目を作ります
- ファイル名は `bgm-cropped.mp3` のように、`-cropped` と選んだ形式の拡張子を付け、保存先を選んで保存します。保存先で拡張子を `.mp3`、`.flac`、`.opus`、`.ogg`、`.m4a`、`.wav` のどれかに変えると(Opus の `.opus` と `.ogg` は同じ中身として扱います。Ogg Vorbis は `.ogg` だけです)、その音源から書ける形式ならその形式で書き出します(中身と拡張子が食い違うと、開き直したときやゲームエンジンで形式を読み違えるため)。それ以外の拡張子のときと、その形式ではループの開始が削れるときは、セレクトの形式で書き、拡張子が合わないことを知らせます
- 壊れたフレーム(FLAC の CRC が合わないものや、mp3 の復号できないもの)が区間にあると、その部分を無音にして書き出し、その数を知らせます。ブラウザは壊れたフレームを飛ばしてデコードすることがあり、その後ろでは、波形で選んだ位置と書き出した位置がずれることがあります
- FLAC で、ブラウザがデコードした長さと FLAC の長さ(kiln が数えたもの)が違うときは、壊れたフレームをブラウザが飛ばしていて位置がずれるので、警告を出して書き出せないようにします
- 保存先に元の音源そのものを選ぶこともできます。音源はクロップモードに切り替えたときに読んでおくので、元の音源がその場で切り詰めた内容に置き換わります。ブラウザは保存先を選んだ時点でそのファイルを空にするので、書き出しに失敗すると空のまま残ります

書き出すと、次のようになります。

- 書き出した音源を開き、ループモードに戻ります。元の音源はセレクトに残ります
- ループを決めていた音源なら、前を切った分を引いた秒数で、書き出した音源の項目を作ります。元の音源の項目も残します。JSON の保存は別の操作で、それまでは未書き出しと表示します
- ループを決めていない音源なら、項目は作りません。全体がループ区間のままです。書き出した名前の項目がすでに JSON にあれば、別の音源の値なので消し、未書き出しと表示します

ループを決めた音源で、クロップの範囲がループ区間にかかっている間は、警告を出して書き出しを止めます。線を区間の外へ動かすか、ループモードで区間を動かしてください。

再生は前端から後端まで 1 回で止まり、ループしません。線を動かすと止まります。

## JSON の保存

| 操作 | 内容 |
|---|---|
| JSON を書き出す | 保存先を選んで保存します |
| 上書き保存 | 読み込んだ(ボタンでもドロップでも)、または保存した JSON に上書きします |
| JSON をコピー | クリップボードにコピーします |

- 保存はファイル全体の置き換えです。ほかの音源の項目を残すには、先にその JSON を読み込みます
- 読み込んだあとにファイルが外から変更されていたら、上書きする前に確認します
- コピーは書き出し済みとして扱いません
- 再読み込みすると、読み込んだ音源と未保存の変更は消えます。未書き出しの変更があるときは、閉じる前にブラウザの確認が出ます

## JSON の形式

ファイル名ごとに、`loopStart` と `loopEnd` を秒で持ちます。`duration` はデコード後の長さ(秒)です。

```json
{
  "bgm.mp3": {
    "loopStart": 10.5,
    "loopEnd": 50.25,
    "duration": 60
  }
}
```

- 秒で持つのは、鳴らす側のサンプルレート(`AudioContext` のレートなど)が音源と違ってもずれないようにするためです。小数 6 桁に丸めるので、サンプル境界からごくわずかにずれることがあります
- `duration` がない JSON も読めます。音源を開いた時点で補います
- `duration` と音源の長さが 1ms を超えて違うと、警告を出します。区間を動かすと、今の音源の長さで記録し直します
- 区間を動かしていない音源は、JSON に書きません。読み込んだ JSON にある項目と、音源の項目の中の知らないフィールドは残します。ただし、クロップで同じ名前の音源を書き出すと、その項目を置き換えるか消します(「クロップ」を参照)
- 音源の項目でないキー(`$schema` など)や、値が正しくない項目が 1 つでもあると、ファイル全体を読み込みません
- ファイル名の順に並べて書くので、差分が読みやすくなります

`AudioBufferSourceNode` には、次のようにそのまま渡せます。

```js
const src = ctx.createBufferSource();
src.buffer = buffer;
src.loop = true;
src.loopStart = loops[name].loopStart;
src.loopEnd = loops[name].loopEnd;
src.connect(ctx.destination);
src.start(0, 0);   // 頭から鳴らすと、イントロを 1 回流してからループ区間を繰り返す
```

## 注意点

- **mp3 の先頭と末尾の無音**: mp3 にはエンコーダが入れる数十ミリ秒の無音があります。長さの情報(LAME ヘッダ)があるファイルは、取り除くかどうかがブラウザのデコーダによって違い、同じ秒でも位置がずれることがあります。ずれるときは WAV に書き出してください。Ogg / Opus も候補ですが、ブラウザによってはデコードできないことがあります。クロップで書き出した mp3 には、kiln が長さの情報を書きます
- **サンプルレート**: 音源は元のサンプルレートのままデコードし(レートは、kiln でファイルのヘッダーから読みます。kiln が切り出せない音源(MPEG-2 の mp3、µ-law の WAV、連結した Ogg など)でも読めます。Opus は常に 48kHz です)、波形、ゼロクロス、「サンプル」の値を元の音源のサンプルで扱います。再生も、音源と同じレートの `AudioContext` で行い、出力の機器のレートへの変換はブラウザに任せます(レートの違う `AudioContext` で鳴らすと、`AudioBufferSourceNode` が線形補間で変換し、高域が落ちて雑音が乗るためです)
- **元のレートが分からない音源**: .aac(ADTS。ヘッダーから HE-AAC かどうかが分からないため)と、SBR があるかどうかが書かれていない m4a(22.05kHz 以下の AAC など)は、出力の機器のレートに変換してデコードします。中身から形式を判定できない音源と、拡張子が .mp3 でない mp3(mp3 は中身に印がないので、読み違えを避けるために拡張子でも確かめます)も同じです。kiln を読み込めなかったときや、調べている途中で失敗したときも、同じ扱いにして音源を開きます。ヘッダーのレートの後ろに「(変換後)」と出します。ゼロクロスは変換後の波形で探すので、別のサンプルレートで鳴らすと、ゼロクロスからわずかにずれることがあります

## デプロイ

Cloudflare Workers の静的アセットとして `dist/` を配信します。サーバー側の処理はありません。設定は `wrangler.jsonc` にあります。

公開版は、`main` に push するたびに [Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/) が自動でデプロイします。ビルドの Node は `.node-version` で指定します。Workers Builds には Zig がないので、ビルドのたびに `npm run build` が Zig を取ってきて kiln の wasm をビルドします。失敗しても公開版は前のバージョンのままで、失敗は Cloudflare のダッシュボードのビルド履歴で確認します。手元で確認したり、手動でデプロイしたりするときは、次のコマンドを使います。

```sh
npx wrangler login   # 初回のみ
npm run build
npx wrangler dev     # dist/ を Workers のランタイムで手元に配信する
npm run deploy       # ビルドして、Cloudflare にデプロイする
```

- `wrangler dev` と `wrangler deploy` はビルドしません。`npx wrangler deploy` を直接実行すると、古い `dist/` を公開するおそれがあるので、`npm run deploy` を使ってください
- 手動でデプロイするときは、レビュー前の内容を公開しないように、`main` で実行してください
- Workers Builds の設定はリポジトリに含まれません。fork で自動デプロイを使うときは、`wrangler.jsonc` の `name` と `account_id` を接続先の Worker に合わせ、Cloudflare のダッシュボードでリポジトリを接続して、ビルドコマンドに `npm run build` を指定してください
- `wrangler.jsonc` の `account_id` は、デプロイ先の Cloudflare アカウントです。fork して自分のアカウントにデプロイするときは、書き換えてください
- デプロイすると、`<name>.<サブドメイン>.workers.dev` を誰でも開けます(`name` は `wrangler.jsonc` の Worker 名)。音源はサーバーに送りません
- `public/_headers` の CSP で、外部への通信と他サイトへの埋め込みをブラウザに止めさせます。`'wasm-unsafe-eval'` は、音源の解析とクロップの書き出しに使う kiln(wasm)のために許可しています。ページの遷移など、CSP で止められない経路もあります。CSP が付くのは Cloudflare と `wrangler dev` の配信だけで、`npm run dev` には付きません
